# cuda_libs

This is the cuda_libs library, a small library I made to generate cuda bindings for rust. 

# autogen

The autogen folder contains the code that autogenerates the bindings for cublas, cublas_lt, cudart, cudnn, cufft, curand, cusolver, cusparse, and the cuda driver api. The autogenerated bindings are stored under cuda_libs_xxx respectively. The autogenerated bindings sys.rs represents the raw bindgen output, and the bindings in safe.rs represents an extremely thin wrapper around the binding. types.rs contains any manually implemented types. I would like to stress that this is an extremely low level library, and the safe wrappers only wrap the errors into enums and wraps the create and destroy functions.

# cuda_rustc

`cuda_rustc` is an nvcc-style rustc wrapper that lets you write CUDA kernels as ordinary Rust functions and launch them with native chevron syntax. Invoked via `RUSTC_WRAPPER=cuda_rustc`; unknown args pass through to the underlying rustc, recognized args drive the cuda pipeline.

The wrapper does four things on every `.rs` source it sees:

1. **Text-level rewrite** — `kernel<<<g, b>>>(args)` is not valid Rust, so a comment/string-aware tokenizer rewrites it to a `cuda_rustc_runtime::launch::launch_kernel(...)` call before rustc parses the file. Host and device arms are cfg-gated; the device arm dispatches via `cudaLaunchDevice` for dynamic parallelism.
2. **AST extraction** — syn walks the rewritten source, finds `#[global]` fns, moves their bodies into a separately-compiled `nvptx64-nvidia-cuda` device crate, and replaces each host-side definition with a `pub static <name>: KernelHandle`. The mod walker recurses into every `mod foo;` (external + inline) so kernels can live in any file and be imported with `use crate::module::kernel`. Top-level structs/consts reachable from a kernel signature are copied into the device crate.
3. **PTX post-processing** — `#[shared] static mut X: T;` markers get their PTX state space rewritten from `.global` to `.shared`; dynamic shared (`static mut SDATA: &mut [f32];` with no RHS) becomes an `.extern .shared` declaration.
4. **Compile-time link + fatbin pack** — `ptxas -c` produces a relocatable cubin, `nvlink` resolves cudadevrt symbols against `libcudadevrt.a`, and `fatbinary` bundles per-arch cubins (driven by `CUDA_ARCH=sm_80,sm_120`) into a real CUDA fatbinary blob. The blob is embedded in the host binary's `.nv_fatbin` section with an nvcc-shaped `__fatBinC_Wrapper_t` in `.nvFatBinSegment`, so `cuobjdump` reads the output normally.

`#[global]` and `#[shared]` are passive marker names recognized textually by the preprocessor — no proc-macro crate; the wrapper strips them from the cached output before rustc sees the source.

The companion runtime crate `cuda_rustc_runtime` exposes `KernelHandle`, `launch_kernel` (host arm = `cuLaunchKernel`, device arm = `cudaLaunchDevice`), and a `register_fatbin` entrypoint that the wrapper's generated ctor calls once at startup. The runtime calls `cuModuleLoadData` on the embedded fatbin and the CUDA driver picks the right arch.

`cuda_rustc` also ships three companion shims for IDE / dev tooling:

- `cuda_rustfmt` — replaces chevron sites with placeholder macro calls, runs plain `rustfmt`, restores chevrons.
- `cuda_clippy` — runs clippy-driver through the same wrapper.
- `cuda_rust_analyzer` — LSP proxy that strips chevrons + `#[global]`/`#[shared]` from `textDocument/didOpen`+`didChange` text before forwarding to a real rust-analyzer backend.

The `cuda_toolchain_build` bin assembles a rustup-shaped directory at `target/cuda-toolchain/` symlinking the shims into `bin/rustfmt`, `bin/rust-analyzer`, etc.; `rustup toolchain link cuda <path>` exposes it as a per-crate `rust-toolchain.toml` channel.


# cuda_rustc_test

Smoke test for the `cuda_rustc` pipeline. Lives in its own detached workspace with `rust-toolchain.toml` pinning the `cuda` toolchain. Covers `print_arr`, `reduce_add`, `translate_points` (non-`repr(C)` host struct on device), `dyn_reduce` (dynamic shared memory), `parent_launch` (kernel-from-kernel via cudaLaunchDevice + cudadevrt), `transpose_2d` (2D grid/block + `#[shared]` tile), `cudart_device_probe` (device-side cudart calls), and `nested_kernel` (kernel reached through inline mod → external mod). Kernels are split across `src/main.rs`, `src/kernels.rs`, and `src/nested/leaf.rs` to exercise the mod walker.
